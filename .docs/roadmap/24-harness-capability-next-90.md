# Harness capability — next 90 moves

This is the current execution order for VANTARI. Rank combines operator value,
downstream leverage, integrity risk removed, and friction removed. The strategic
north star remains sharded, token-minimal execution; the current source and
runtime evidence make serialized lifetime, ledgers, and durable workers its
required foundation.

Execute in numeric order inside each shared owner surface. Parallel work is
valid only when patch surfaces do not overlap. A source-present change does not
advance the queue until the real installed consumer path proves it.

## Governing invariants

1. Let the model choose the next eligible action. Keep hardcoded logic for
   capability truth, durability, budgets, evidence, recovery, and explicit
   irreversible-action gates.
2. Control voice, pace, initiative, delegation posture, work intensity,
   narration, and interaction cadence through the hot-loaded prompt envelope.
3. Preserve the default burst loop: choose one observable step, act, inspect,
   emit a compact checkpoint, and continue. Let prompts tune its cadence.
4. Run every move through an add, consolidate, or delete decision. Completing
   all 90 means closing every decision with evidence, not adding 90 mechanisms.
5. Add no abstraction until the current capability needs it and the existing
   owner cannot absorb it. Remove dead branches, config, prompts, registries,
   wrappers, and fallback paths during the owning move.
6. Prove prompt personalization with behavior-profile tests. At minimum cover
   terse/detailed, solo/orchestrated, conservative/aggressive, and low/high
   update cadence without alternate executor logic.
7. Scale context through selective awareness, not transcript replication. Agents
   exchange bounded sequence-addressed messages and pull summaries or artifacts
   on demand. Tickets remain the only work lifecycle.
