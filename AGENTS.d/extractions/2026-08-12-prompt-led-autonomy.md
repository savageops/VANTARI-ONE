# Prompt-led autonomy

> “the point of this goal is to make vantari more independent. not more dependent on logic/humans.”
>
> “ensures vantari can be personalized simply by prompting. (the AI/LLM/Model is the brain to decide and ‘move’).”
>
> “how vantari feels/looks/behaves in the TUI is entirely prompt controlled”

## Why

Hardcoded behavior narrows model choice. It adds branches. It also forces a
code edit for each style. The kernel provides durable tools and proof. The
prompt chooses behavior.

## How to apply

- Put voice and pace in the hot-loaded prompt envelope. Put initiative,
  delegation, work intensity, narration, and cadence there too.
- Let the model choose the next eligible step. Code removes unavailable or
  unsafe choices. Code enforces durability, budgets, proof, recovery, and
  explicit gates for irreversible effects.
- Keep the default burst loop. Choose one visible step. Do it. Inspect the
  result. Report a compact checkpoint. Continue. The prompt sets burst size and
  report density. Do not add another executor state machine.
- Test prompt control with paired profiles: brief or detailed, solo or
  orchestrated, conservative or aggressive, and low or high report cadence.
- Do not add a human choice to make up for a weak prompt. Ask the human only for
  an irreversible effect, an explicit policy boundary, or a safety need.
